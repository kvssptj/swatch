# Improve a weak interface

## Purpose

Learn whether the model can diagnose design problems instead of copying the source.

## What you need

- One interface with clear usability or visual problems.
- A short description of the product and user.

## Prompt

> Evaluate the supplied interface in the context of the product, intended user, and primary task. Identify the usability and visual problems most likely to interfere with that task, and explain the evidence for your priorities. Distinguish observable issues from hypotheses that would require user research.
>
> Redesign the screen to address the highest-priority problems. Preserve necessary information and useful product behavior while improving hierarchy, labels, grouping, navigation, and feedback where relevant. Consider readability and accessibility. Remove or simplify elements only when you can explain why doing so helps the user.
>
> Deliver a revised screen as an editable design or working implementation, according to the supplied materials. Connect the main changes to the problems they solve, describe any tradeoffs, and identify what you would validate with users before shipping.

## What to observe

- Does the model find the important problems?
- Does it set clear priorities?
- Does the redesign solve the stated problems?
- Does it add unnecessary features or decoration?
